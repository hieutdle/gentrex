# Benchmark design

gentrex-bench measures how often Gentrex gets a genetic test report right,
and which command loses a value when it doesn't. It runs on three kinds of
report: synthetic reports with a known truth, sample reports that labs
publish, and later real reports that two people annotate. The same scorer
scores all three.

The generator of synthetic reports and the scorer are built.
[How the benchmark generator works](benchmark-generator.md) explains the
generator, [Generate benchmark reports](generate-benchmark-reports.md) shows
how to run it, and [Run the benchmark](run-benchmark.md) how to run Gentrex
on the reports and score it. The work on public and real reports is still to
come.

## What it takes from other benchmarks

The design borrows from benchmarks in other fields. The last column says
whether gentrex-bench does it yet.

| Benchmark | What it does | What gentrex-bench does with it | Built |
| --- | --- | --- | --- |
| [TPC-H](https://www.tpc.org/TPC_Documents_Current_Versions/doc/tpc-h_v3.0.1.docx), for databases | Its `dbgen` program makes the same test data on every machine from a fixed seed. | `generate.py sample` makes the same cases from the seed in `settings.yaml`. A test checks this across two Python processes. | yes |
| TPC-H | Every published result comes with a [Full Disclosure Report](https://www.tpc.org/results/fdr/tpch/hpe~tpch~30000~hpe_proliant_compute_dl580_gen12~fdr~2026-06-11~v02.pdf) of the hardware, the settings and the price. | `manifest.json` records the settings and a checksum of each reference file. Each truth file records the model that wrote the report and the Chrome version. `scores.json` keeps the `run.yaml` of every command with the scores. | yes |
| TPC-H | Its run rules forbid code that only exists to win the benchmark. | Nothing in Gentrex may react to what only synthetic reports have, such as their footer. | rule only |
| [Artificial Analysis](https://artificialanalysis.ai/methodology/intelligence-benchmarking), for LLMs | It runs every model itself with the same test setup, repeats the tests whose scores vary, and gives 95% confidence intervals. | Every model goes through the same Gentrex commands on the same frozen test set, three times, with bootstrap confidence intervals. | the intervals |
| Artificial Analysis | It shows each model's accuracy next to its speed and price. | A plot of report accuracy against GPU-hours per 1,000 reports, in `evaluation_results/pipeline.ipynb`. | yes |
| [GIAB and GA4GH](https://pmc.ncbi.nlm.nih.gov/articles/PMC6699627), for variant calling | Every tool's variants are matched and counted the same way. A variant found with the wrong genotype counts apart from one not found. | The scorer matches variants by gene and DNA change first, and then scores zygosity, classification and the rest. | yes |
| GIAB and GA4GH | Results are split by variant type and region. | Every case records its lab, test, result and challenge tags, so results can be split by each. Each tag is in 11 to 24 of the 200 test cases, and each template in 8 to 12. | yes |
| GIAB and GA4GH | Only regions where the truth is certain are scored. | Where a real report is ambiguous, the annotators give both readings and either one counts. | no |
| [CAMI](https://pmc.ncbi.nlm.nih.gov/articles/PMC6368784), for metagenomics | One simulation gives the truth for every step of the analysis. | One truth file holds the page texts for `gentrex transcribe`, the record for `gentrex extract` and the IDs for `gentrex normalize`. | yes |
| [n2c2](https://pmc.ncbi.nlm.nih.gov/articles/PMC7489085), for clinical NLP | Two people annotate each document, and a third settles disagreements. Matches are scored strict and lenient. | The same protocol for real reports, and both ways of matching. | the matching |
| [Weber et al. 2019](https://pmc.ncbi.nlm.nih.gov/articles/PMC6584985), guidelines | Simulated data has a known truth, but it must look like real data. | The truth comes from real ClinVar, HPO and MONDO records. Reports have distractors, held-out labs and scanned copies. Public sample reports and real reports will show how far synthetic results carry over. | partly |

Two ideas don't carry over. TPC-H scales its data up because databases slow
down as data grows, but Gentrex reads each report on its own, so 200 reports
show its speed as well as 10,000 would. Artificial Analysis also combines its
tests into one index. Gentrex would need weights between its measures for
that, and there is no good reason for any choice of weights, so report
accuracy stays the main number.

## Closest earlier work

[Yu, Weile and Courtot](https://www.medrxiv.org/content/10.64898/2026.01.19.26344287v1.full)
(OICR, medRxiv, January 2026) made 1,000 molecular test reports from seven
LaTeX templates, with text generated by code, and a "faxed" copy of each.
GPT-4.1-mini reached an average F1 of 55.6 on them, and the best local model,
Gemma 3, 41.3. The faxed copies lowered F1 by 38.8%.

They didn't test real reports, and they averaged F1 only over answers that
were valid JSON. A model that often fails to answer looks better that way.
Their generator is on GitHub at
[courtotlab/PDF_benchmarking](https://github.com/courtotlab/PDF_benchmarking),
so Gentrex can also be run on their reports.

## Generator

[How the benchmark generator works](benchmark-generator.md) describes the
generator step by step. Its design rests on a few decisions.

The truth of a case is fixed before any text is written. Code picks the
values and prints them in a report template, and a language model writes
only the free text around them. A model that wrote the truth along with the
report could contradict itself, with a protein change that doesn't follow
from the DNA change, or a table and a paragraph that give different
zygosities.

The 21 templates are drawn after the rendered pages of the public sample
reports (see [Public sample reports](#public-sample-reports)). An earlier
version had the model write the whole report as HTML, from a description of
the layout. Its reports differed from one another in look, and values
sometimes went missing or overlapped their labels. With templates, every
report of a template looks the same, as a real lab's reports do, and the
model writes about 1,500 tokens of text instead of a whole page of HTML.

The reports are PDFs because Gentrex reads PDFs, and its first step,
`gentrex transcribe`, is where real reports go wrong, in wrapped table cells,
columns and scanned pages. Headless Chrome prints them. WeasyPrint could do
the same without a browser, but it supports less CSS.

The image PDFs copy the pages that the public reports revealed, page images
whose only text is a short code (see
[Public sample reports](#public-sample-reports)). They check that
`gentrex transcribe` keeps sending such pages to OCR. To check that
the scan and fax damage looks real, print and fax 20 reports once, and
compare their OCR errors with those of the two levels.

The writing model must not be a Gemma model, because Gentrex extracts with
Gemma and would then read text that its own model family wrote. A hosted
model is fine, because the reports hold no patient data.

## Benchmark set

The first version has 300 cases in 21 report templates. They cover panels,
exomes, genomes, single genes, carrier screens, the mitochondrial genome,
tests of one known variant, chromosomal microarrays, karyotypes, repeat
expansions in FMR1, HTT and C9orf72, SMN1 copy numbers and methylation tests
for Prader-Willi and Angelman syndromes.

| Part | What it is |
| --- | --- |
| Dev set | 100 cases, for tuning Gentrex's prompts and settings |
| Test set | 200 cases, frozen. At 90% accuracy, 200 reports give a 95% confidence interval of about ±4 points, and at 70% about ±6. |
| Templates | Three of the 21 templates appear only in the test set: the image-only genome cards, the carrier screen grid and the lab-system printout. They show how Gentrex does on layouts it wasn't tuned on. |
| Versions | Each report comes as a native PDF, a scan, a fax, a mixed PDF and an image PDF, all with one truth. Comparing them shows what scanning costs. |
| Version name | A folder name such as `v1`. Results compare only within one version. |

Gentrex trains no model, but every change made after reading its wrong
records fits it to those reports. That holds for the questions and
`select.keep_threshold` of `gentrex select`, for `extract.instruction` and
the descriptions in the schema of `gentrex extract`, and for the rules and
the HPO models of `gentrex normalize`. Accuracy on reports that were used
this way comes out too high. The test set is therefore scored only with
settings that were decided on the dev set.

Every report has all five versions. The alternative would give each version
to a share of the reports, such as scans to a fifth of them. With all five,
the runs on native PDFs and on scans read the same reports, so a drop in
accuracy comes from the scanning alone and not from harder cases. No share
has to be chosen either. How many reports arrive scanned or faxed differs
between hospitals, and a reader can weigh the accuracy of each version by
their own mix.

The templates get about the same number of cases. Each of the 18 templates
of the dev set gets 5 to 7 cases, and each of the 21 templates of the test
set gets 8 to 12. The numbers can't be equal, because the
shares of the tests are fixed first, and a template only gets cases of the
tests it reports.
[How the benchmark generator works](benchmark-generator.md#templates) lists
the count of each template.

Every JSON and HTML file of a version holds a canary string, and the native
and image PDFs have it in their title. It's a fixed sentence with a random
ID, as BIG-bench uses, that lets model makers keep the set out of their
training data.

## Truth files

Each report gets one JSON file, in the formats Gentrex itself writes.

| Key | Holds |
| --- | --- |
| `case` | The split, lab, test, result, challenge tags and writing model |
| `record` | What `gentrex extract` should write, with the page of each variant |
| `normalized` | What `gentrex normalize` should add |
| `pages` | The text of each page of the native PDF |
| `distractors` | Values the report prints that must not be extracted |
| `canary` | The canary string |

Annotators will fill the same file for real reports, without `pages`, so one
scorer serves both.

## Scorer

The scorer, in `gentrex-bench/scorer/`, reads a folder of truth files and a
run of Gentrex, and writes tables and a JSON file with every detail.
[Run the benchmark](run-benchmark.md) shows how to run it and read its
output.

### Counting

Every field of every report counts as one of these:

| Truth | Gentrex | Counts as |
| --- | --- | --- |
| value | same value | correct |
| value | null | missed |
| null | value | extra |
| value | other value | wrong, which is both missed and extra |
| null | null | correct |

A strict match needs the exact text. A lenient match ignores case, spacing
and trailing punctuation, and accepts HGVS written another way, such as
`c.5266dupC` for `c.5266dup`. The scores use the lenient match, and the
table of fields also gives the share of strict matches. Fields with a fixed
list of values compare the category. `overall_result_raw` is compared through its category, because
there's no single right place for the copied text to end.

Variants are matched one to one by gene and DNA change, and each matched pair
is then scored on its other fields. A variant with a wrong DNA change
therefore counts as one missed and one extra variant. An extra variant is a
distractor error if the report prints it as a distractor, and a
hallucination if it doesn't.
Clinical features match by text for `gentrex extract` and by HPO ID for
`gentrex normalize`. The ClinVar ID of a variant with a c. change is scored
when `gentrex normalize` looked the variants up in ClinVar.

### Main numbers

Report accuracy is the share of reports with nothing clinically wrong. The
result category and the karyotype are right, every variant's gene, DNA
change, copy number, classification and zygosity are right, and no variant
is extra.

The scorer also gives the variant F1, with misses and extras split by cause,
and the share of reports with both the MRN and the date of birth right,
because a wrong MRN files the result under another patient. A table gives
the accuracy of every field.

### Where errors come from

Each lost value is charged to the first command that lost it:

| The value is | Charged to |
| --- | --- |
| missing from the transcribed text | `gentrex transcribe` |
| on a page that wasn't kept | `gentrex select` |
| wrong or missing in the record | `gentrex extract` |
| right in the record, with a wrong date, category or ID | `gentrex normalize` |

An extra value is charged to the command that wrote it. Results are split by
seen and held-out lab, by challenge tag, by number of variants and by
result. Each run reads one PDF version, so the versions are compared across
runs.

`gentrex extract` names the copied values that it can't find in the pages'
text. The scorer measures this check against the truth. It gives the share
of the named values that were wrong or extra, and the share of all wrong or
extra copied values that were named.

### Statistics and cost

Confidence intervals come from a bootstrap that resamples whole reports,
because the fields of one report aren't independent. Two setups are compared
on the same reports, with an interval for their difference. The final setup
runs three times, to show how much runs differ. A report without a record
counts as all missed, and is never dropped. A record that lacks pages is
scored as it is, so the values on those pages count as missed.

Every command saves its time and the token counts that the model server
returns in its `run.yaml`. The scorer reads them and gives the time, the
tokens and the GPU-hours per 1,000 reports. `gentrex-bench/run.py` also
records the GPUs and the vLLM version.

## Run rules

1. Tune on the dev set only. Score the test set only for the numbers you
   report.
2. Report every run, not only the best one.
3. Use the same settings for native and scanned reports.
4. Nothing in Gentrex may react to what only synthetic reports have, such as
   their footer.
5. Keep with every result the Gentrex version and commit from `run.yaml`, the
   settings, the models, the vLLM version, the GPUs and the benchmark
   version.

## Public sample reports

Genetics labs publish sample reports with made-up patients. They have the
layouts of real reports, with no patient data, so they sit between the
synthetic and the real reports. `gentrex-bench/public/catalog.csv` lists 61
that Gentrex's schema covers: 19 from Ambry Genetics, 14 from Blueprint
Genetics, 14 from PreventionGenetics, 8 from Labcorp, 3 from ARUP
Laboratories, 2 from Invitae and one from the NHS. They include cancer
panels, exomes, genomes, carrier screens, microarrays, karyotypes, repeat
expansions, a methylation test and single-variant tests.

The NHS entry is the supplement of a study of reports that patients can
understand ([Recchia et al. 2020](https://doi.org/10.1038/s41436-019-0649-0),
CC BY 4.0). It shows four reports of a cystic fibrosis carrier test, as
images. The two-page report written with patients has a page in plain
language first and the technical details second, and the standard report
has one page. Both follow UK conventions, with dates written day first, the
NHS number and risk figures such as "1 in 4".

A first look at the PDFs, without running Gentrex, found a weakness in it.
Six Ambry reports are full-page images whose only text is a document code of
24 characters. Two Labcorp reports draw their text as outlines and keep only
the form's placeholders as text. `gentrex transcribe` read a page with 20 or
more characters of text as native, so it skipped OCR and lost these pages.
It now also sends a page to OCR when images cover at least half of it and it
has fewer than 300 characters, or when it has at least 1,000 curves and
fewer than 600 characters.

The generator's templates come from these reports. They were sorted into 21
layout families, by header design and by how they show the result. Each
family became a template, and `gentrex-bench/generator/labs.py` names the
reports that each one follows (`based_on`).

The two-page enterprise report also reports FMR1 repeat sizes and SMN1 copy
numbers, as LAB05 and LAB08 do, and the genome cards a uniparental disomy, as
AMB17 does. The one-line summary template reports panels, microarrays, HTT
and C9orf72 repeats and the methylation test, as the PreventionGenetics
reports do, and prints the ClinVar ID of each variant. Labcorp's diagonal "SAMPLE REPORT" watermark is left out,
because its letters mix into the text of the values and the check could no
longer find them.

Because the templates follow these reports, their layouts are no longer new
to a Gentrex that was tuned on the synthetic dev set. Scores on the public
reports then measure how Gentrex handles real files of familiar layouts.

The sample reports have limits. Three labs make up 47 of the 61, and sample
reports are tidier than real ones. The labs haven't allowed anyone to share
them, so the repository holds only links and checksums, and a lab can change
or remove a file. None of the reports is annotated yet.

## Real reports

Only real reports show how accurate Gentrex is in practice. 150 annotated
reports give about ±5 points at 90% accuracy.

Take them at random, from all labs and from both native and scanned PDFs,
and from reports nobody looked at while building Gentrex, such as a later
time window. Two people annotate each report from the PDF, without seeing
Gentrex's output, because people tend to accept what they're shown. A genetic
counselor settles their disagreements. Scoring one annotator against the
other gives the human ceiling.

The scoring runs on [Minerva](../minerva/minerva.md), and only the summary
tables leave it, because the error lists quote patient data.

Synthetic accuracy describes only the mix of cases that was generated. What
the synthetic set can show is whether it ranks setups the same way as real
reports and finds the same weak fields. Where it doesn't, the generator is
missing something, and that gap becomes a new challenge tag.

## Next steps

1. Generate the full synthetic set with the model in `settings.yaml`.
2. Annotate the 61 public sample reports in the truth format.
3. Run Gentrex on 20 synthetic cases as a pilot. Fix the generator where it's
   wrong, not Gentrex.
4. Freeze version 1, publish its PDFs and truth files, and run the final
   setup three times.
5. Get ethics approval, then annotate and score the real reports.

Who annotates the public and real reports is still open. Two people and a
genetic counselor would be ideal.
